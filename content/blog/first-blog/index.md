## Introduction

After years of wrestling with frameworks, databases, and build pipelines for what amounted to a personal blog, I went back to basics: plain static HTML, generated once and served forever.

## Why Static Won

- **Speed**: No server-side rendering, no database round-trips — just files.
- **Simplicity**: A markdown file in, an HTML file out. Nothing to patch or update at 2am.
- **Ownership**: No vendor lock-in, no subscription, no mystery outage.

## The Trade-off

Static sites aren't great for anything that needs real-time interactivity or user accounts. But for a portfolio or blog, that's rarely the point.

## Conclusion

Static isn't old-fashioned — it's just honest about what a blog actually needs.
